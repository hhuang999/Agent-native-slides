# Element Design Language

Agent-Native Slides — 元素层设计语言

元素层定义最小粒度的设计决策：标题格式、正文密度、间距节奏。
这些规则跨所有风格通用；各风格通过 CSS token 覆盖具体数值，但结构不变。

---

## 1. 标题格式（Assertion-Evidence）

所有幻灯片标题必须是**完整断言句**，而非短语或主题词。

| ✅ 正确 | ❌ 错误 |
|---------|---------|
| Attention is all you need for sequence modeling | Attention Mechanism |
| 三层神经网络已足够逼近任意连续函数 | 通用近似定理 |
| Chinchilla scaling shows data matters as much as parameters | Scaling Laws |

**长度上限**
- 中文：≤12 汉字（含标点）
- 英文：≤10 个实词
- 中英混排：≤15 字符

**字号比例**
- 断言标题与正文的字号比例应制造张力，不应温柔渐变
- 具体数值由 `--text-hero` / `--text-title` / `--text-body` token 决定
- 标题可以很大，但须在实际可用宽度内完整显示；正文不能为了塞下内容而刻意缩小
- 在 1920×1080 舞台上，演讲型正文建议 28–36px，密集阅读页正文至少 24px，重要图表标签至少 22px；18–22px 仅用于非核心图注和来源。所选风格的较小预览字号不能覆盖此规则。

---

## 2. 正文内容密度

### density: speaker（默认）
观众不读幻灯片，演讲者口头补充：
- 每页 **1 个主张** + **1 个视觉证据**
- 正文文字量 ≤ 30 字（英文 ≤ 25 词）
- 禁止 4 级以上的嵌套列表
- 禁止超过 3 个平行要点（列表就要讲完，讲不完就拆页）

### density: reading（文档型）
观众自行阅读，无演讲者在场：
- 每页正文初稿总量 ≤ 80 字（英文 ≤ 60 词），至多两个文本块；实际排版若拥挤，还要继续缩减
- 可用有限的列表，但每项应是短句；完整解释放入备注或拆成续页
- 必须有清晰的视觉锚点（数字、图、图标）

### 内容与字号的处理顺序

1. 先把说明、背景和限定条件移入 `speaker_notes`，保留断言、证据和必要标签。
2. 调整图文比例、列宽、留白和对齐；若有两个视觉重心或标题超过两行，拆页。
3. 只有在仍清晰可读、且不低于上述正文建议时，才微调字号与行距。不要用 `transform:scale()` 缩字、负字距、`line-clamp`、省略号或 `overflow:hidden` 隐藏必要文字。
4. 字数只是初稿预算。字体加载完成后，以 `check-deck.js` 的屏幕和打印检测及实际截图为准。

## 3. 间距与节奏

所有间距从 8px 基准衍生（4px 用于紧密细节）：

```css
/* 已在 RUNTIME.md 定义，此处为语义说明 */
--space-xs:  8px   /* 同组元素内间距（label ↔ value） */
--space-sm:  16px  /* 同块元素间（段落内部） */
--space-md:  32px  /* 内容区域间（标题 ↔ 图表） */
--space-lg:  64px  /* 主要模块间（标题区 ↔ 正文区） */
--space-xl:  96px  /* 页边距（stage 四周） */
```

**留白是构成手段**：一个干净的空白区域比填充一个"相关"图标更有力量。

在 1920×1080 舞台四周预留约 80–96px 安全边距。先为断言标题保留足够高度，再给图表和正文划分互不挤压的区域；文字容器优先使用可增长的高度，不用固定高度裁切正文。

## 4. 版式结构原则

### 每页视觉重心

一页最多 **1 个主视觉重心**（图表/图/公式/代码）。
如果有 2 个平等的视觉重心，拆成两页。

### Z 型 vs F 型阅读路径

- **单一断言页**：Z 型 — 标题（左上大字）→ 视觉证据（右下/中心）
- **对比页**：F 型 — 标题（顶部）→ 左列 → 右列

### 层次深度

不超过 3 层视觉层次：
1. **英雄元素**（断言标题 / 主图）— 最大、最粗、最亮
2. **支撑元素**（数据、图表、说明文字）— 中等
3. **辅助元素**（注释、来源、页码）— 最小、最淡

---

## 5. 文字对齐

| 场景 | 对齐方式 |
|------|---------|
| 断言标题 | 左对齐（英文）/ 左对齐（中文） |
| 大数字 KPI | 左对齐或居中（一致即可） |
| 图注/图例 | 与图保持一致 |
| 禁止 | 两端对齐（justify）— 会产生不均匀字间距 |

---

## 6. 色彩使用原则

遵循 **1 主色 + 1 点缀** 规则：

- 主色：`--color-accent`，用于最重要的 1 个视觉角色（高亮行、数据条、关键词下划线）
- 点缀：仅允许出现在 ≤2 处，不超过整页面积的 5%
- 禁止：4 色平权配色、彩虹图表

---

## 7. 图标使用

- 来源：Lucide（ISC）或 Phosphor Icons（MIT）
- 风格：与风格保持一致（细线 vs 填充 vs 像素）
- 大小：不小于 20px，不大于 48px（装饰用途除外）
- 搭配文字时：图标与文字基线对齐，间距 `--space-xs`

---

## 8. 禁用列表（Anti-Slop）

永远不出现以下元素：

| 禁用 | 原因 |
|------|------|
| Bullet point + sub-bullet + sub-sub-bullet | 视觉噪声，说明内容未整理 |
| 装饰性分割线（每页底部粗线） | 会增加视觉重量而不承载意义 |
| "Thank you" 结束页（仅有文字） | 视觉浪费，改用总结断言 |
| 多于 2 种强调方式（加粗+斜体+下划线+颜色） | 什么都强调 = 什么都没强调 |
| 纯白底+蓝色标题+黑色正文 | PowerPoint 默认视觉语言 |
| 渐变色文字（linear-gradient clip text） | 低级感溢出 |
| 4 种或更多颜色在一页平权出现 | 色彩无秩序 |

---

## 9. 图片使用

- 装饰性图（封面背景、section 分隔背景）：AI 生成，不影响文字可读性
- 数据图表：永远用 ECharts — 不用图片 API 替代
- 示意图/架构图：SVG 手工绘制，使用 CSS token 着色
- 图片叠文字：必须有足够的对比度（WCAG AA 4.5:1）

---

## 10. 中文版式特殊规则

- 标题与正文字体须成对出现（衬线标题 + 无衬线正文，或反之）
- 中文段落行高 ≥ 1.8（英文 ≥ 1.5）
- 中英混排时，英文字体先加载，中文备用字体作 `unicode-range` 覆盖
- 标点挤压：建议使用 `font-feature-settings: "chws" 1`（OpenType 中文标点压缩）
- 禁止全角英文数字（会造成视觉节奏断裂）
